# Managed reliability acceptance

This record covers spec #39 and tickets #40–47. Product behavior and managed
setup have separate owners: Skillwick owns discovery, selection, reads, and
canonical instructions; `agent-state` owns installation, required capabilities,
session environment, and managed publication. No production apply, package
activation, authentication, or release was performed.

on arm64 macOS, with an isolated installation prefix. The executable reports
`skillwick 0.4.0`; its SHA-256 is
`b6e4b9532d44ed561527a4676c92c87c9438d2da62f412dfc3c223f2d249b754`.
It was installed again from clean revision
`d02972512774cb4b8ad983fd95e543132fa8adda` after the reviewed product changes.
This is a source installation,
not a published release. Canonical instructions have SHA-256
`eef0c01faab57edb5f0274b78fa667df45819cfbd73bd8607802a44c9fa5e676`.

`make check` passed: formatting, Clippy, Rust tests, benchmark/profile contracts,
offline reranker contracts, public CLI/setup/discovery/invocation contracts,
distribution smoke, documentation, and trust-boundary checks. The filesystem
integration suite passed separately. CLI, setup, discovery, invocation,
documentation, and trust checks also passed against the controlled installed
executable. Locked dependency advisory, license, and source checks passed;
the informational staleness report did not change the lockfile.
The staged commit hook ran its full suite and controlled
source-install acceptance. Its automatic sources were isolated fixture homes;
this is distinct from the blocked workstation provider below.

Selection proof covers returned IDs and exact names, grouped verified copies,
genuine name conflicts, denied selection, changed bodies, moves/removal,

The read-only workstation baseline reports Skillwick 0.4.0 from a source
installation whose existing receipt identifies revision
`d02972512774cb4b8ad983fd95e543132fa8adda` and a dirty
checkout. Its executable and canonical instruction hashes now match the controlled
installation above; this was a read-only refresh after external workstation
changes. The configured explicit managed roots resolve `astra-orchestrator`,

unavailable there. Strict required health exits 3, so a required batch cannot

or activated to manufacture a passing baseline.

historical queries are retained unscored; six bounded synthetic positives rank
first, while both negative controls return candidates. Those failures remain
unfixed. Intended-corpus qualification and backend comparison remain pending
coverage correction by the package owner. Ranking evidence does not establish
agent selection, instruction use, or task success.
